# 比赛主机迁移说明（2026-10-22）

## 已检查的结论

当前算法没有发现 CUDA、cuDNN、TensorRT、ROCm、HIP、Intel OpenVINO/MKL 等专用推理后端或硬件 SDK 的使用。数字模型通过 OpenCV DNN_BACKEND_OPENCV + DNN_TARGET_CPU 运行，模型文件是 models/armor_num_cnn.onnx。传统灯条、PnP、跟踪、能量机关、导航使用 CPU。源代码和实际编译参数没有 -march=native、特定 AMD/Intel 指令集选项。8 个安装节点在加载 ROS 和两个工作区后 ldd 无缺失依赖，未出现 GPU 专用动态库。OpenCV 的 HighGUI、RViz 和比赛 Unity 的图形显示仍需要主机有正常的桌面及图形驱动，但算法不要求 NVIDIA CUDA。

这是对当前工程及本机库的检查，不等于已经在尚未接触的比赛主机上运行验证。主机的 Ubuntu/ROS 版本、通信消息和比赛程序版本仍需现场确认。

## 当前已验证环境

- Ubuntu 24.04.4 LTS，x86_64。
- ROS 2 Jazzy，脚本固定 source /opt/ros/jazzy/setup.bash。
- C++17，系统 OpenCV 4.6.0，Eigen3、nlohmann_json、cv_bridge。
- Python3：rclpy、numpy、yaml、ament_index_python；地图工具另使用 cv2。
- CMake、g++、pkg-config、colcon，ROS launch/launch_ros、rviz2、tf2_ros 和消息生成依赖。

Intel CPU + NVIDIA GPU 本身不构成已发现的不兼容。若主机只有 Windows，不能直接执行本 Linux/ROS 工程；若 ROS 是 Humble 等其他发行版，也不能只改 source 路径就认为适配完成。请先核对系统和 /opt/ros 下的版本。

## U盘带什么

推荐携带 Desktop 中的 campusgame_比赛主机迁移包_20261023.tar.gz 和同名 .sha256 文件。压缩包顶层是 campusgame，包含完整源码、通信桥和消息定义、ONNX、配置、地图、启动与编译脚本、说明和编辑器配置。排除了本机两层工作区的 install、.build、.logs、__pycache__，防止搬家后继续引用旧绝对路径。没有改变原工程算法或清理原电脑的编译结果。

也可以额外复制整个 campusgame 作为保险备份，但不要依赖其中旧的 install 和 .build 在新机器上直接运行。不要拿 campusgame_teaching 代替比赛工程。

tar.gz 会保存脚本执行权限，适合通过 exFAT/FAT 等U盘文件系统传输。把压缩包复制到主机本地硬盘再解压，不建议在U盘上编译和运行。如主机已有同名 campusgame，先解压到新的测试目录，避免覆盖他人或已有调试内容。

## 现场步骤

1. 查看 `cat /etc/os-release`、`uname -m`、`ls /opt/ros`、`pkg-config --modversion opencv4`。优先使用 Ubuntu 24.04 + ROS Jazzy；系统OpenCV应与该主机 cv_bridge 匹配。
2. 在本地硬盘的新目录解压迁移包，进入其中的 campusgame。下列命令均在该目录执行。
3. 从源码构建：

```bash
bash build_autoaim.sh
```

迁移包没有旧 install，该脚本会先构建通信桥和 tdt_interface，再构建比赛节点。不要把本机的 .build/install 复制回来覆盖新结果。

4. 查看启动参数（不启动比赛）：

```bash
bash run_competition_auto.sh --show-args
```

5. 终端一启动通信桥：

```bash
bash start_bridge.sh
```

6. 使用主机上的正式比赛程序，按其说明连接 ROS。默认桥地址 127.0.0.1、端口10000，适用于游戏与ROS在同一主机。不要重复启动主机已运行的同端口通信桥；先与管理员确认使用哪一套。若游戏在另一台机器，要核对桥监听地址、游戏连接地址和网络设置，不能继续假设127.0.0.1。
7. 终端二进入同一个 campusgame，再启动（蓝方示例）：

```bash
bash run_competition_auto.sh player_id:=1 mask_display:=true
```

红方改 player_id:=2；关闭mask使用mask_display:=false。若桌面窗口有问题，可先 `rviz:=false aim_display:=false buff_display:=false mask_display:=false`，这只关闭可视化，不替代图形驱动和比赛程序的适配。

8. 确认图像/自身状态确实收到、敌我颜色正确、地图对应正式赛场、左右转向和开火正常，再测试完整一局。现场主机性能、帧率与延迟可能不同，先测再决定参数，不能因为换显卡就随意更改瞄准几何或开火条件。

## 缺依赖时

如果主机已经配置好 Jazzy 和赛事依赖，直接构建即可。若缺包，在管理员允许下使用该主机发行版对应的包或 rosdep 安装工程 package.xml 中的依赖。常见 Ubuntu/Jazzy 包包括：build-essential、cmake、pkg-config、python3-colcon-common-extensions、libopencv-dev、libeigen3-dev、nlohmann-json3-dev、python3-numpy、python3-yaml、python3-opencv、ros-jazzy-cv-bridge、ros-jazzy-ament-cmake、ros-jazzy-rosidl-default-generators、ros-jazzy-rclcpp、ros-jazzy-rclpy、ros-jazzy-launch-ros、ros-jazzy-rviz2、ros-jazzy-tf2-ros，以及标准消息包。此列表用于定位缺项，不是在未知系统上直接安装的通用命令；不需要为本工程额外安装CUDA或PyTorch。

## 路径和消息注意事项

源码中的 /home/tdt 出现于历史操作注释和 landmark_alignment.json 的 source_pairs 元数据，不是当前运行读取模型/地图的绝对路径。模型默认用 ament 安装包路径，地图也由包路径定位。旧构建缓存和 setup 文件中有旧路径，所以迁移包不携带生成目录。

必须带上通信桥内的 tdt_interface 和主工程 campus_aim_interfaces。若赛方已经提供同名消息包，要核对字段与本工程源码一致，避免在混合的 ROS 环境中误加载其他版本。若正式游戏消息与本工程接口不同，需要现场按赛方接口适配，不能仅靠显卡信息作保证。

## tdt_interface 找不到时（截图 CMakeLists.txt:5）

若失败包为 campus_aim_interfaces，且第5行 find_package(tdt_interface REQUIRED) 报错，缺的是本工程通信消息包的 CMake 配置，不是显卡库。新版 build_autoaim.sh 每次先增量构建通信工作区，成功后加载 local_setup 并检查 tdt_interfaceConfig.cmake，再显式把其所在目录传给主工程 CMake。原来仅检查 local_setup 文件是否存在的逻辑，不能识别不完整或搬移后的 install。

请将包复制到主机硬盘，在新文件夹解压并执行 bash build_autoaim.sh。若单独执行 colcon，只构建主工程而未构建/加载通信包，也会出现相同报错。旧包临时修复顺序：

```bash
bash campusgame_ros/ros2_auto_framework/build.sh
source /opt/ros/jazzy/setup.bash
source campusgame_ros/ros2_auto_framework/install/local_setup.bash
bash build_autoaim.sh
```

通信工作区编译失败时，先处理它的第一条错误，不能继续主工程。未确认主机完整环境前，不需要改算法或安装CUDA。

## 根因补充：中文构建目录使 rosidl 路径被截断

若通信包报 rosidl_generate_interfaces.cmake:234 list index 1 out of range，随后 Target dependency '/media/.../campusgame_' does not exist，与中文构建路径有关。本机复现：rosidl_adapter 的 file(STRINGS ...) 未指定 UTF-8，将一条包含校园赛中文目录名的路径拆成中文之前与之后的两个片段，前段缺少IDL元组分隔符，所以报列表下标越界。前面的 tdt_interfaceConfig.cmake 找不到是通信包构建失败后的下游错误。

请先把 tar.gz 压缩包复制到主文件夹，然后在主文件夹终端执行（压缩文件名可以含中文，但解压后的工程完整路径必须为ASCII，建议无空格）：

```bash
mkdir -p "$HOME/campus_ascii_20261023"
tar -xzf "$HOME/campusgame_比赛主机迁移包_20261023.tar.gz" -C "$HOME/campus_ascii_20261023"
cd "$HOME/campus_ascii_20261023/campusgame"
bash build_autoaim.sh
```

使用未带旧install/.build的源码包重新解压，不要只改旧文件夹名称后继续使用缓存。新版两个构建入口会先检查ASCII路径，遇到非ASCII字符直接给出说明。已经用全英文路径构建过的本机代码无需为这项检查重新编译算法。
