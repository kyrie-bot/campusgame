# 参数位置与生效顺序

参数分为启动参数、YAML 基础配置、实际比赛组合参数及源码中的固定条件，不能只看某一个 YAML 数值就认定它是最终运行值。

## 运行时参数

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 阵营、巡航速度、是否打符、前哨站/基地距离范围 | `src/stage1_comm_test/launch/competition_auto.launch.py` | `DeclareLaunchArgument` 定义默认值，可在启动命令中覆盖 |
| 检测、数字分类、PnP、跟踪和自瞄 | `src/stage1_comm_test/config/autoaim.yaml` | 由 `tools/autoaim_profile.py` 读取，再按阵营和协调控制模式组合 |
| 全局规划、敌情、任务与收益 | `src/stage1_comm_test/config/arena_navigation.yaml` | 规划器基础配置 |
| 底盘跟随与反馈超时 | `src/stage1_comm_test/config/arena_following.yaml` | 跟随器基础配置，不是所有比赛最终值 |
| 比赛速度、加速度、坡道限速、高地和坡口配置 | `src/stage1_comm_test/tools/competition_training_profile.py` | `training_parameters()` 在基础 YAML 上覆盖实际比赛参数 |
| 地图大小、地形和坡道 | `src/stage1_comm_test/config/reference_terrain.yaml` | 当前生成地图的几何来源，带摘要校验，不应随意改写 |
| 地图发布 | `src/stage1_comm_test/maps/arena_reference/runtime.yaml` | 栅格尺寸、分辨率、目录及标注开关 |

当前比赛组合中，默认巡航指令上限为 `4.2 m/s`（原 `3.5`）、加速度上限 `8.5 m/s²`（原 `6.5`）、转弯横向加速度上限 `2.8 m/s²`（原 `2.0`），坡道速度上限跟随巡航值。普通前视距离 `2.0 m`（原 `1.8`），坡道前视距离 `1.6 m`（原 `1.1`），减少追逐眼前短路段造成的减速。巡航启动参数允许 `0.2–4.5 m/s`，节点启动校验同步支持该范围。

以上是控制器的指令限制，比赛引擎和实测运动反馈仍决定实际速度。弯道、制动、碰撞预测和反馈检查仍可降低实际速度。制动模型保持 `1.2 m/s²`，没有用未经验证的更强制动力缩短停车距离；反馈超时、碰撞余量和地图边界保持原值。参数位于 `competition_training_profile.py`，因此不能把 `arena_following.yaml` 中的基础 `0.6 m/s` 误认为比赛最终巡航值。

例如只覆盖巡航上限：

```bash
./run_competition_auto.sh player_id:=1 cruise_speed_mps:=3.0
```

所有启动参数可通过 `./run_competition_auto.sh --show-args` 查看。

修改源码后执行 `./build_autoaim.sh` 再重启比赛程序。修改 YAML、模型或其他安装资源后也重新构建，保证 `install/` 中使用的是修改后的内容。

大符的 `BuffSolution.header.stamp` 是弹道瞄准轨迹的时间原点；新增角速度、角加速度字段单位为度/秒和度/秒²。云台输出补偿最多 80 ms 的解算传递时间，超过范围就等待新结果。`big_rune_gimbal.hpp` 使用最多 300 ms 的时间戳配对实测偏差预测执行时刻的枪口角度；小符沿用原反馈路径。修改内部消息后须重新构建并重启整套自动程序，避免新旧节点混用。

## 大符漏击恢复与换板

- `buff_detection/big_rune_cycle.hpp`：只有耗弹已确认且新图像仍显示待击打板，才判断漏击。使用耗弹状态捕获时间约束最晚弹着时刻，再留 60 ms 观察余量；两帧独立图像至少跨 25 ms。第一发未命中时仍使用原首击窗口，不把发弹当作已命中。两发均未命中时每块板最多一次补击；已经确认命中的板保持锁定。
- `buff_detection/buff_node.cpp`：等待弹着时持续预测仍亮着的目标；大符未耗弹重试等待由 300 ms 调整到 200 ms，小符仍为 300 ms。候选发弹时更新弹丸飞行时间，日志 `RUNE_AMMO_CONFIRMED` 记录耗弹约束的发弹延迟区间。
- `buff_detection/final_rune_accuracy.hpp`、`aiming/combat_gimbal.cpp`：换板/初次获取时使用已有 120°/s 上限，稳定跟踪仍使用原修正幅度；开火需要实际反馈验证。
- `buff_detection/big_rune_observation.hpp`：融合同帧待击打板的相位和深度，已完成圆环不进入大符运动拟合。

规则窗口结束时等待下一轮，不对已经失效的旧板补弹。小符单发令牌的 20 ms 脉冲与最短 100 ms 令牌间隔保持原值。

## 敌方机器人命中检查

- `config/autoaim.yaml` 的 `aim_solver.command.mobile_plate_window_scale` 当前为 `1.0`。`aiming/fire_control.hpp` 中的 `mobileFireWindow()` 按距离、朝向和倾角计算矩形开火窗口，并扣除 6 mm 边缘余量；即使旧配置写入大于 1 的值，也不能扩大实际装甲尺寸。近距离正面目标仍保留原来的快速确认。
- `aiming/fire_control.hpp` 的 `mobileBallisticWindow()` 用重力弹道与预测运动装甲平面求交，检查实际反馈角度和输出命令的弹着点。它还考虑枪口随云台转动的位置变化。仅机器人编号 1–5、7 使用此检查；前哨站、基地和能量机关沿用各自逻辑。
- `aiming/aim_solver.cpp` 的短时丢识别续射还须满足装甲实际宽高允许的预测精度；不再仅用固定 0.12 m 标准差上限授权。预测不确定时继续瞄准，等待可靠观测。
- `AimSolution.msg` 将原始弹道角、窗口大小和本次计算时间与原有编号、槽位、角度、许可一起发送。`aiming/combat_gimbal.cpp` 使用最新反馈复核；计算超过 35 ms 不再沿用旧开火许可。原有 120 ms 续射缓存不能绕过当前解算的许可或恢复旧角度盲射。
- 日志 `MOBILE_BALLISTIC_WINDOW` 表示预测弹着点不在装甲有效范围；`WAIT_MOBILE_EXECUTION_ALIGNMENT` 表示最终反馈/计算时效复核未通过。解算日志新增 `number` 和 `range`，便于区分机器人编号与跟踪 ID，并核对距离。

本次变更涉及内部 `AimSolution` 消息，构建后需退出旧节点并重新启动整套比赛程序。调节窗口不能补偿错误的相机标定、实际弹速或装甲尺寸；这些参数应依据测量修改。

## 四号车无出弹时的站位调整

- `aiming/aim_solver.cpp`：四号车仅从当前观测或已学习的装甲槽位中选板。整车几何尚未确认时优先保留实测板；短丢失时可在已见过的板位上继续原有预测。其他编号保持原来的选板行为。
- `aiming/ballistics.hpp`：`intercept()` 和 `interceptMovingShooter()` 的 `allowed_slots` 位掩码限制候选板位；默认仍允许全部槽位。
- `navigation/combat_policy.hpp`：`FourthNoFireAdvance` 记录弹量、四号车血量和停车持续时间。完整视角下连续 **2 秒**（原 3 秒）没有耗弹或伤害进展时，同一站位允许一次前移；实际耗弹或伤害进展会更新计时。离开原站位超过 **0.8 m**、敌车血量回升或新局会重新建立记录。移动过程中、反馈/任务不允许、无弹药时不累积停车计时。
- `navigation/path_follower.cpp`：无出弹调整优先计划 **0.65 m**（原 0.30 m），越界或不安全时依次尝试 0.48、0.30 m，只执行其中最长的安全路段。沿当前 Dijkstra 路线保留转弯，并逐段检查 **0.03 m** 栅格余量和当前高地边界。此调整不用通用侧向脱困；均不安全时保留停车。使用正常跟随器的制动和到达判定；最长 **3 秒**，同一站位不循环前移。
- 四号车失去完整装甲视角后的前进段由 **0.8 m 增至 1.4 m**，最多 5 秒，完整视角恢复时仍立即回到交战停车。四号车通用接近步长上限由 **1.8 m 增至 2.4 m**，接近控制器使用正常巡航上限，取消单独的 1.8 m/s 限制；近距离制动和完整装甲停车条件保留。
- 继续耗弹时保持原来的完整装甲停车规则。日志 `FOUR_NO_FIRE_ADVANCE`、`four_no_fire_forward=1` 表示这一次调整正在执行。

这些数值目前在上述 C++ 位置，修改后需构建并重启比赛节点。原有装甲物理开火窗口、前哨站和大小符参数保持不变。
